# 04 — Speaking Spec

> **Historical proposal.** This file preserves the visual/state-machine exploration, not the shipped microphone interaction contract. The current challenge uses press-and-hold to record, release to submit once, and written results without TTS. See [10 — Shipped User Flows](10-shipped-user-flows.md).

The 45-second challenge, end to end. This wraps the existing `speaking` feature (`app/lib/features/speaking/**`, contributed separately, clean-architecture, already functional) in the new visual language — it does not replace any of its domain/data logic. Everything in §2 and §4 already exists in code today; the redesign changes presentation only.

## 1. What already exists (read before designing anything new)

- **State machine**: `SpeakingChallengePage` (`presentation/speaking_challenge_page.dart`) holds a private `enum _Phase { ready, recording, analyzing, feedback, comparison, denied, error }`, driven by plain `setState`.
- **Recording**: `SpeechRecorder` interface (`domain/speech_recorder.dart`) — `requestPermission()`, `start()`, `stop() → Uint8List`, `cancel()`, `Stream<double> get amplitude`, `dispose()`. Implemented by `RecordSpeechRecorder` (`data/record_speech_recorder.dart`) wrapping `package:record ^7.1.1`.
- **Amplitude is already live and already wired to the bubble** — see `05-bubble-state-machine.md` §1 for the full evidence trail; this spec only needs the fact that it exists.
- **Analysis**: `SpeechAnalysisRepository.analyze(Uint8List audio, {required String mimeType, required Duration duration}) → Future<Result<SpeechTranscript>>`, three implementations (`http`, `supabase`, `fake`) wired via `speechAnalysisRepositoryProvider`. The Supabase implementation calls the `speech-analyze` Edge Function.
- **Local metrics vs. LLM coaching are two separate things** — don't conflate them when designing the feedback screen: `SpeakingMetrics` (filler-word count, pause count, words-per-minute) is computed **locally** by `SpeechAnalyzer` (`domain/speech_analyzer.dart`) from the transcript's word timestamps, no network round-trip. `SpeechCoaching` (`summary`, `structure`, `vocabulary`, `strength`, `retryCue`) comes from the LLM via the Edge Function and is optional on `SpeechTranscript` (may be absent if the LLM call fails but transcription succeeded).
- **Backend contract** (`supabase/functions/speech-analyze/handler.ts` + `index.ts`): `POST {audioBase64, mimeType, durationMs}` → `200 {text, durationMs, words: [{text, start, end}], analysis: {summary, structure, vocabulary, strength, retryCue}}`. `mimeType` must be one of `audio/wav`, `audio/webm`, `audio/ogg`, `audio/m4a`. `durationMs` must be `500–60000`. Payload capped at 5 MiB. Transcription: Groq Whisper `whisper-large-v3-turbo`, `language: es`, word-level timestamps. Evaluation: Groq `llama-3.3-70b-versatile`, `temperature 0.2`, forced JSON, explicitly instructed to evaluate only textual evidence (no invented tone/pronunciation/emotion — the model never claims to hear anything). Error mapping: upstream 429 → `429 rate_limited`, other upstream failure → `502 upstream_error`, empty transcript → `422 no_speech`.
- **No feature flag** gates speaking — it's a plain always-on route today (`/speaking/challenge`), moving into the shell per `02-navigation-model.md`.

|---|---|---|---|
| **Prompt** | `ready` | Today's speaking prompt (topic + `SpeakerCueCards` structure hints: abre/conecta/cierra), streak, last attempt's summary if any, start CTA | Becomes the Habla tab's landing state (`02-navigation-model.md`). Prompt text sized `displayL`/`titleL`, not buried in a card — this is the moment that has to sell "just talk for 45 seconds," so it gets editorial treatment, not a form. |
| **Prepare** | `ready` (pre-start sub-state, no separate enum value) | `SpeakerCueCards` progressive reveal — same widget, unchanged | Bubble is present but idle (breathing, `05-bubble-state-machine.md`), signalling "ready when you are" without demanding action yet. |
| **Record** | `recording` | Live timer, amplitude-reactive bubble, cue cards still visible for reference | Bubble becomes `SpeakingBubble`/`AudioReactiveBubble` (`07-component-hierarchy.md`) — same amplitude pipeline as today's `VoiceOrb`, new rendering (shader on capable platforms, painted fallback on web — `05-bubble-state-machine.md` §2). `TrainingTimer` counts up to the 45s soft cap (see §3). |
| **Analyse** | `analyzing` | Bubble transitions to a processing state (no amplitude input anymore — mic is closed), short "escuchando tu grabación" message | This is the one phase with no user input at all — keep it brief and honest about what's happening (never a bare spinner; the brand voice rule against sterile/robotic copy applies here). |
| **Feedback** | `feedback` | `SpeakingMetrics` (WPM, fillers, pauses — computed instantly, no wait) shown first, `SpeechCoaching` (summary/structure/vocabulary/strength/retryCue) shown once it arrives, retry CTA | New `FeedbackCard` (`07-component-hierarchy.md`) composes both; if `SpeechCoaching` is null (LLM call failed but transcription succeeded), the card degrades to metrics-only with a plain-language note, never a raw error. |
| **Retry** | back to `recording` (new attempt), previous transcript retained in page state | Same recording UI; `retryCue` from the previous attempt's coaching (if present) can be surfaced as a one-line reminder above the bubble | No new domain state needed — `SpeakingChallengePage` already re-enters `recording` for a retry; the redesign only needs to keep the *first* attempt's `SpeechTranscript` in memory for §"Compare." |
| **Compare** | `comparison` | Side-by-side (or stacked on compact width) of attempt 1 vs. attempt 2 metrics, and coaching if both have it | This phase exists in the enum today; confirm with the founder whether it's fully implemented end-to-end or a stub — worth a direct code check before `09-implementation-plan.md` sizes this step, since the research pass for this document did not confirm its current completeness beyond the enum's existence. |
| Permission denied | `denied` | Explanation + link to system settings | Unchanged; not a design priority for this pass beyond restyling to the new component set. |
| Any failure | `error` | Distinguish the three backend error shapes for copy purposes: `rate_limited` ("dale un segundo, vamos a intentarlo de nuevo"), `upstream_error` ("no pudimos escuchar bien esa, ¿lo intentamos otra vez?"), `no_speech` ("no detectamos nada — ¿tu micrófono está encendido?") | Copy differentiation matters here — a generic "algo salió mal" for all three loses information the backend already gives you for free. |

## 3. The 45-second constraint

The backend accepts `durationMs` up to 60000 (60s) — a safety margin above the product's 45-second challenge, not a mismatch. The UI enforces the 45s cap, not the backend: `TrainingTimer` counts up, and at 45s either auto-stops the recording (recommended, keeps the challenge honest and short) or switches to a visibly-different "overtime" state up to a hard ceiling (e.g. 55s) before force-stopping — founder should pick one; auto-stop-at-45s is simpler and matches "45-second challenge" as a literal constraint rather than a suggestion. Minimum duration: the backend rejects anything under 500ms, so the UI should disable "stop" (or just not offer it) until at least ~1s has elapsed, to avoid a guaranteed `400` from an accidental tap.

## 4. Audio format

`RecordSpeechRecorder` must produce one of the four accepted `mimeType`s (`audio/wav`, `audio/webm`, `audio/ogg`, `audio/m4a`). This is an existing contract already satisfied by the current implementation (not re-verified format-by-platform in this research pass — confirm `record`'s output format matches per-platform before implementation, since web (`record_web`) and mobile encoders don't always default to the same container).

## 5. What the redesign changes vs. leaves alone

**Changes**: the bubble's rendering (see `05-bubble-state-machine.md`), the prompt/landing screen's typographic treatment, the feedback card's layout, the timer's visual prominence, copy for the three error states, and Habla's promotion into the shell (`02-navigation-model.md`).

**Leaves alone**: `SpeechRecorder`/`SpeechAnalysisRepository` interfaces, the three repository implementations, `speech-analyze`'s request/response contract and Groq model choices, `SpeechAnalyzer`'s local metrics computation, the `_Phase` enum's states (comparison's completeness aside, per §2). This is a wrapping job, not a rebuild.
